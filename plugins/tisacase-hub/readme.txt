منوی واحد همهٔ افزونه‌های اختصاصی + زبان طراحی مشترک + پایش سلامت.

== Description ==

این افزونه «هاب» مجموعهٔ ابزارهای اختصاصی تیساکیس است:

* صفحهٔ **اختصاصی تیساکیس** با کارت همهٔ افزونه‌ها؛ هر کارت در تب جدید باز می‌شود.
* **فعال/غیرفعال کردن** افزونه‌ها از همان کارت، سنجاق کردن، جستجو، ناوبری با کیبورد.
* تزریق **زبان طراحی مشترک** (`tisacase-ui.css`) روی صفحه‌های خودِ افزونه‌ها — بدون آنکه هیچ افزونه‌ای کدی بنویسد.
* **نرمال‌ساز**: دکمه، نوتیس، جدول، فرم، تب و کارت وردپرس داخل همان صفحه‌ها به این زبان درمی‌آید.
* **رنگ برند** و **حالت کم‌فضا** از تنظیمات هاب؛ با یک تغییر، همهٔ صفحه‌ها rebrand می‌شوند.
* **گزارش سلامت**: بررسی ایستای دسترسی‌های باز، مهار ZIP، uninstall، سازگاری HPOS، قلم CDN و فاصله‌گرفتن از توکن‌ها.

هیچ تنظیماتی در افزونه‌های شما نوشته یا تغییر نمی‌کند؛ فقط استایل و منو.

== Installation ==

1. در پیشخوان: افزونه‌ها › افزودن افزونه › بارگذاری افزونه › `tisacase-hub.zip`.
2. فعال‌سازی. یک گزینهٔ مستقل به نام «اختصاصی تیساکیس» در نوار کنار اضافه می‌شود
   (پیش‌فرض: بعد از داشبورد). جایگاهش در تنظیمات هاب قابل تغییر است و هیچ ورودی‌ای
   داخل منوی ووکامرس ثبت نمی‌شود.
3. (اختیاری) فایل‌های `vazirmatn-400.woff2` … `vazirmatn-800.woff2` را در `wp-content/plugins/tisacase-hub/assets/fonts/` بگذارید تا قلم محلی شود.

== Frequently Asked Questions ==

= اگر هاب را غیرفعال کنم چه می‌شود؟ =
صفحهٔ هاب و استایل تزریقی می‌روند؛ صفحهٔ هیچ افزونه‌ای خراب نمی‌شود. افزونه‌ها CSS خودشان را دارند و همهٔ `var()`ها با fallback نوشته شده‌اند.

= چرا هاب زیرمجموعهٔ ووکامرس نیست؟ =
چون یک ابزار مستقل است. فقط یک گزینهٔ بالاتر/پایین‌تر در همان نوار کنار می‌نشیند و
جایگاهش دست شماست (تنظیمات › جایگاه هاب در نوار کنار).

= آیتم‌های منوی ووکامرس/محصولات چه می‌شوند؟ =
با گزینهٔ «مخفی کردن آیتم‌های پخش‌شده» (پیش‌فرض روشن) فقط از منو حذف می‌شوند. URL مستقیم، بوک‌مارک‌ها و صفحهٔ هر افزونه دست‌نخورده است.

= افزونهٔ جدید را چطور اضافه کنم؟ =
یک خط هدر در فایل اصلی افزونه:
`TisaCase Hub: title="نام"; icon=tag; group=pricing; page=admin.php?page=my-page; parent=woocommerce; slug=my-page`
یا با فیلتر `tisacase_hub_items` (نمونهٔ کامل در صفحهٔ تنظیمات هاب هست).

= شمارنده‌های روی کارت‌ها سنگین نیست؟ =
کش ۵ دقیقه‌ای (قابل تغییر در تنظیمات) و فقط با کوئری‌های آماده. با خاموش‌کردن «شمارنده‌ها» هیچ کوئری‌ای اجرا نمی‌شود.

== Changelog ==

= 1.9.12 =
* **رفع باگ «همگام‌سازی کارت نمی‌آورد»:** تابع ادغام فهرست مخزن (`merge_catalog`) در کد بود ولی هیچ‌جا صدا زده نمی‌شد؛ یعنی همگام‌سازی فهرست را ذخیره می‌کرد اما کارت تازه‌ای به صفحه اضافه نمی‌شد. حالا در `TSH_Registry::items()` صدا زده می‌شود و آیتم‌های تازه (مثل `tisacase-exporter`) بعد از همگام‌سازی می‌آیند.
* **فالبکِ بدون API:** اگر فهرست‌گیری `api.github.com` جواب ندهد (سقف ۶۰ درخواست در ساعت برای IP هاست‌های اشتراکی)، هاب خودش پوشه‌های شناخته‌شده را مستقیم روی شاخهٔ تنظیم‌شده با HEAD چک می‌کند؛ شاخه‌های شلش‌دار (مثل `feature/foo`) هم درست resolve می‌شوند.
* **دیگر «آنلاین» دروغ نمی‌گوید:** وقتی فهرست همراه هاب استفاده می‌شود، پیام صریحاً «آفلاین» است؛ در حالت کاوش مستقیم هم پیام مخصوص خودش را دارد. تعداد ابزارهای صفحه در پیام همگام‌سازی نمایش داده می‌شود.
* کارت «مخزن» در تنظیمات، زمان و تعداد آخرین همگام‌سازی را نشان می‌دهد.

= 1.9.11 =
* **توضیح کارت «خروجی گرفتن» به‌روز شد:** حالا پنج بخش (شماره‌ها، سفارش‌ها، مشتری‌ها، محصول‌ها و کدهای تخفیف)، انتخاب ستون، پیش‌نمایش، چهار قالب خروجی (TXT/CSV/اکسل/JSON) و تاریخچهٔ اجراها را معرفی می‌کند — هم‌زمان با انتشار `tisacase-exporter` نسخهٔ ۲٫۰٫۰. زیپ همراه هاب بازسازی شد.

= 1.9.10 =
* **جایگزینی کارت «خروجی شماره تماس سفارش‌ها» با «خروجی گرفتن»:** افزونهٔ `tisacase-order-phone-exporter` بازنشسته شد و جایش را `tisacase-exporter` (نسخهٔ ۲٫۰٫۰) گرفت — همان موتور خروجی شماره‌ها، ولی با هویت تازه و آمادهٔ بخش‌های بعدی (سفارش‌ها، مشتری‌ها، محصول‌ها). کلید رجیستری `phones` → `exporter`، آیکون `upload`، آدرس `admin.php?page=tisacase-exporter`.
* **فهرست همراه (catalog.json) هم به‌روز شد** تا کارت «نصب از مخزن» به زیپ جدید `plugins/dist/tisacase-exporter.zip` اشاره کند (زیپ قدیمی از مخزن حذف شده است).
* اگر افزونهٔ قدیمی روی سایت نصب است: اول آن را غیرفعال/حذف کنید، بعد نسخهٔ ۲٫۰٫۰ را از همین کارت نصب کنید (دو افزونه هم‌زمان = دو کرون و دو پوشهٔ موقت).

= 1.9.9 =
* **رفع خرابی دکمهٔ «همگام‌سازی فهرست»:** فالبک jsDelivr پاسخ مخزن را با ساختار اشتباه می‌خواند و گاهی کاتالوگ را **خالی** ذخیره می‌کرد (همان «افزونهٔ جدید نیومد»). حالا هر دو ساختار (GitHub API و jsDelivr) درست parse می‌شود و **فهرست خالی هرگز کاتالوگ فعلی را پاک نمی‌کند.**
* **کاهش مصرف از limit API GitHub:** خواندن هدر هر افزونه اول با آدرس مستقیم raw (بدون API) امتحان می‌شود و فقط در صورت شکست، فهرست‌گیری از API — یعنی همگام‌سازی کامل تقریباً به ۱ درخواست API می‌رسد به‌جای ~۱۴.
* **پیام خطای روشن برای rate limit:** اگر سقف درخواست GitHub پر شده باشد (رایج در هاست اشتراکی)، پیام فارسی واضح به‌جای «HTTP 403» دیده می‌شود.
* **بازخورد بعد از همگام‌سازی:** بعد از کلیک، تعداد افزونه‌ها و **شاخهٔ همگام‌شده** نمایش داده می‌شود (تا اشتباه شاخه مثل `main` به‌جای شاخهٔ کاری فوراً معلوم شود) + حالت آفلاین (فهرست باندل‌شده) هم جداگانه گفته می‌شود.
* حذف کال‌بک مردهٔ `handle_sync` (مسیر فرم بلا‌استفاده) — همگام‌سازی فقط از دکمهٔ AJAX لانچر است.

= 1.7.1 =
* **کارت افزونه‌های نصب‌نشده حالا دکمهٔ «نصب از مخزن» دارد:** هاب زیپ افزونه را از پایهٔ آدرس مخزن می‌خواند (`TSH_Registry::zip_url()` روی `ZIP_BASE`)، پوشهٔ داخل زیپ را با پوشهٔ مورد انتظار چک می‌کند، با `Plugin_Upgrader` نصب می‌کند و اگر دسترسی بود همان‌جا فعال می‌کند. دیگر لازم نیست برای هر افزونهٔ مجموعه زیپ را دستی دانلود و آپلود کنید.
* **کارت «گروه‌بندی متغیرها بر اساس برند» به فهرست داخلی اضافه شد:** پیش از نصب هم کارت هست (گروه محصول و محتوا، آیکون `grid`) و از همان‌جا یک‌کلیک نصب می‌شود؛ بعد از نصب هم مثل بقیه از هدر خودش کشف می‌شود.
* **تنظیمات → «نصب از مخزن»:** پایهٔ آدرس زیپ‌ها قابل تغییر شد (`zip_base`) — برای تست شاخهٔ دیگر یا مخزن دیگر. فیلترهای `tisacase_hub_zip_base` و `tisacase_hub_zip_url` هم اضافه شدند.
* افزونه‌های بازنشسته (قیمت گروهی، قیمت‌گذاری داینامیک) دکمهٔ نصب نمی‌گیرند چون زیپی در مخزن ندارند؛ همهٔ ۱۰ کارت دیگر آدرس زیپ معتبر دارند (از جمله `wc-telegram-orders.zip` که نام فایلش اصلاح شد).

= 1.6.0 =
تجمیع نسخه‌های ۱٫۳٫۰ تا ۱٫۶٫۰ (بستهٔ نصب همین نسخه):
* **کشف خودکار افزونه‌های تازه:** رجیستری، هر افزونه‌ای را که هدر `TisaCase Hub:` داشته باشد از خودش می‌خواند (کلید، گروه، آیکون، صفحه، دسترسی، توضیح) و کارت می‌سازد — دیگر برای افزودن افزونهٔ جدید لازم نیست کد هاب عوض شود. اگر کلیدی در فهرست پیش‌فرض باشد، مقادیر هدر رویش ادغام می‌شود.
* **آپدیت از روی کارت:** هر کارت ابزار «بارگذاری زیپ» گرفت (`handle_update`): بررسی می‌کند پوشهٔ داخل زیپ با پوشهٔ نصب‌شده یکی باشد، بعد `Plugin_Upgrader` با `overwrite_package` نصب می‌کند، حالت فعال قبلی را برمی‌گرداند و کش افزونه‌ها را پاک می‌کند.
* **کارت «ارسال سفارش‌ها به تلگرام»** به رجیستری اضافه شد (گروه سفارش‌ها، آیکون `send`).
* **اعلان‌های هاب** از بنر بالای صفحه به قرص شیشه‌ای داخل هیرو منتقل شدند؛ پیام‌های موفق خودشان محو می‌شوند، دکمهٔ بستن دارند و `tsh_msg`/`tsh_err`/`tsh_item` از URL پاک می‌شود (بدون رفرش اضافه).
* **جاروی فایل‌های آزمایشی:** `sweep_temp_write_tests()` هم بعد از هر آپدیت از روی کارت و هم روی `upgrader_process_complete` فایل‌های صفر بایتی `temp-write-test-*` را در ریشه‌های شناخته‌شده پاک می‌کند.
* **نوتیس‌های مزاحم:** `mute_foreign_notices()` در صفحهٔ هاب/صفحه‌های افزونه‌های همین مجموعه، فقط اعلان‌هایی را نگه می‌دارد که فایل کال‌بک‌شان داخل همان افزونه است (`callback_file()`).
* CSS/کارت‌ها: بازطراحی پاصفحهٔ کارت و ابزارها، دکمهٔ «باز کردن» تنها نقطهٔ پررنگ هر کارت.
