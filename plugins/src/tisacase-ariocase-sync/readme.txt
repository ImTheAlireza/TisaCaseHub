جفت‌کردن دو محصول موجود با SKU یا Product ID و تبدیل لینک محصول TisaCase یا ArioCase به شناسه؛ فقط و فقط برای سینک موجودی.

== Description ==

هر جفت یک کارت با دو فیلد مستقل شناسه دارد؛ یکی برای TisaCase و دیگری برای ArioCase:

`AR120 - AR22`

اگر شناسهٔ یکی از دو فروشگاه را ندارید، لینک محصول را در «تبدیل لینک به شناسه» وارد کنید. فروشگاه از روی دامنه تشخیص داده می‌شود و SKU واقعی برای کپی نمایش داده می‌شود. اگر محصول ArioCase فقط Product ID داشته باشد، خروجی قابل‌کپی `ID:<product_id>` است. برای محصول متغیر، منوی «انتخاب Variation» باز می‌شود و شناسهٔ همان متغیر کپی می‌شود؛ شناسهٔ والد برای اتصال پیشنهاد نمی‌شود. برای Variation تیساکیس همواره `ID:<variation_id>` یکتا کپی می‌شود تا SKU مشترک بین والد و Variationها مانع اتصال نشود. کارت نتیجه در حالت اولیه مخفی است و بعد از تبدیل، مرتب و تمام‌عرض زیر فیلد لینک نمایش داده می‌شود.

قالب خطی قبلی با دو SKU و قالب لینک‌دار نسخهٔ 1.3.0 برای سازگاری در لایهٔ پردازش حفظ شده است. لینک ArioCase با وب‌سرویس و لینک TisaCase از روی محصولات همان وردپرس Resolve می‌شود.

* کارت‌های جمع‌وجور با دو Input شناسه، پیش‌نمایش کارتی و دکمهٔ کپی شناسه.
* هر دو محصول باید از قبل وجود داشته باشند؛ هیچ محصولی ساخته نمی‌شود.
* فقط نگاشت داخلی و موجودی تغییر می‌کند.
* نام، قیمت، SKU، تصویر، توضیحات، ویژگی‌ها و وضعیت انتشار کپی یا سینک نمی‌شوند.
* هر SKU تیساکیس و هر کد ArioCase فقط در یک جفت فعال قرار می‌گیرد.
* پیش‌نمایش دو محصول قبل از اتصال و خواندن دوبارهٔ موجودی تازه هنگام اجرا.
* پشتیبانی از محصول ساده با ساده و Variation با Variation؛ والد متغیر مستقیماً سینک نمی‌شود.
* دریافت Variationهای محصول متغیر در تبدیل‌کننده؛ ID یکتا برای تیساکیس و SKU یا مرجع ID برای آریوکیس.
* کنترل موجودی در افزودن به سبد، سبد و تسویه‌حساب با تجمیع تعداد هر قلم.
* عدم تبدیل Timeout، خطای HTTP یا JSON خراب به موجودی صفر.
* گزارش ۱۰۰ رویداد آخر بدون ذخیرهٔ Token و ثبت در TisaCase Hub.

== Installation ==

1. ووکامرس را فعال کنید و از سایت نسخهٔ پشتیبان بگیرید.
2. فایل `tisacase-ariocase-sync.zip` را از پیشخوان › افزونه‌ها › افزودن › بارگذاری نصب و فعال کنید.
3. به ووکامرس › جفت موجودی ArioCase › تنظیمات API بروید.
4. آدرس پیش‌فرض را حفظ کنید، روش Bearer را انتخاب و Token را در API Key وارد کنید.
5. با یک لینک، SKU یا مرجع `ID:<product_id>` واقعی «تست اتصال» را اجرا کنید.
6. اگر شناسه را ندارید، لینک TisaCase یا ArioCase را در «تبدیل لینک به شناسه» وارد کنید؛ برای محصول متغیر ابتدا Variation را از منو انتخاب کنید. در تیساکیس ID یکتای Variation و در آریوکیس SKU یا ID خروجی را کپی کنید.
7. در کارت جفت، شناسهٔ تیساکیس و آریوکیس را در فیلد مربوط به همان فروشگاه قرار دهید؛ برای دستهٔ بزرگ‌تر «افزودن جفت» بزنید.
8. پیش‌نمایش را بررسی و فقط جفت‌های تأییدشده را متصل کنید.

== ArioCase API contract ==

تنظیمات پیش‌فرض برای قرارداد اعلام‌شدهٔ ArioCase آماده است:

* Base URL: `https://ariocase.com/wp-json/wc/v3`
* Auth: `Authorization: Bearer YOUR_TOKEN`
* جست‌وجوی کد ArioCase: `products?status=publish&per_page=100&sku={code}`
* تشخیص لینک Pretty/Plain Permalink: `products?status=publish&per_page=100&slug={slug}`
* لینک کوتاه `?p={id}`، مرجع مستقیم `ID:<product_id>` و دریافت محصول شناسایی‌شده: `products/{id}`
* دریافت جزئیات تنوع‌ها هنگام نیاز: `products/{parent_id}/variations`
* خواندن موجودی تنوع شناسایی‌شده با مرجع `ID:<parent_id>/<variation_id>`: `products/{parent_id}/variations/{variation_id}`

پاسخ List با کد دقیق و حساس‌به‌حروف بررسی می‌شود. در مراجع `ID:<product_id>` و `ID:<parent_id>/<variation_id>`، IDهای پاسخ باید دقیقاً با مرجع درخواستی یکی باشند؛ ورودی عددی بدون پیشوند `ID:` همچنان SKU است. در حالت لینک، Host باید با دامنهٔ API تنظیم‌شده یکی باشد، خود صفحهٔ محصول Fetch نمی‌شود و Slug پاسخ باید دقیقاً با لینک یکی باشد. Product ID و Parent/Variation ID فقط برای یافتن همان محصول در درخواست‌های بعدی نگهداری می‌شوند.

== TisaCase link resolver ==

لینک TisaCase با Host سایت جاری تشخیص داده و بدون HTTP Request خارجی Resolve می‌شود. لینک کوتاه با Product ID و لینک `?product=slug` با محصول همان نامک خوانده می‌شود؛ Pretty Permalink با Rewrite خود وردپرس به Product ID تبدیل می‌شود. برای محصول متغیر، Variationهای واقعی همان وردپرس با مرجع `ID:<variation_id>` بازگردانده می‌شوند و SKU در برچسب گزینه باقی می‌ماند؛ بنابراین SKU مشترک هم قابل‌استفاده است. SKU خالی در محصول ساده، لینک غیرمحصول و دامنهٔ ناشناس رد می‌شود.

== Security and stock behavior ==

* HTTPS الزامی است و Redirect دنبال نمی‌شود تا Token به مقصد دیگر منتقل نشود.
* Token نمایش داده نمی‌شود و از خطاها و گزارش‌ها حذف می‌شود.
* می‌توانید Token را با ثابت `TISACASE_ARIOCASE_API_KEY` در wp-config.php قرار دهید.
* خطای API به معنای موجودی صفر نیست و موجودی صفر را در دیتابیس بازنویسی نمی‌کند.
* با نگهبان خرید فعال، خرید قلم متصل هنگام نبود امکان بررسی موجودی متوقف می‌شود.
* حذف افزونه فقط نگاشت‌ها و تنظیمات خودش را پاک می‌کند؛ محصولات حذف نمی‌شوند.

== Frequently Asked Questions ==

= آیا نام یا قیمت هم بین دو فروشگاه سینک می‌شود؟ =
نه. هیچ فیلد محصول به‌جز `manage_stock`، `stock_quantity` و `stock_status` تغییر نمی‌کند. نگاشت و شناسه‌های API هم فقط Meta داخلی افزونه هستند.

= چه لینک‌هایی پشتیبانی می‌شوند؟ =
لینک محصول TisaCase یا ArioCase با Pretty Permalink مثل `/product/case-slug/`، نامک در Query مثل `?product=case-slug` و لینک کوتاه `?p=123`. دامنه باید با سایت جاری یا ArioCase تنظیم‌شده یکی باشد. لینک دسته‌بندی، برچسب یا دامنهٔ دیگر پذیرفته نمی‌شود. برای Variation، لینک والد را در تبدیل‌کننده وارد و متغیر را از منو انتخاب کنید؛ در تیساکیس ID یکتای Variation و در آریوکیس SKU یا مرجع ID همان Variation ساخته می‌شود.

= اگر SKU والد و Variationهای تیساکیس یکسان باشد چه می‌شود؟ =
از تبدیل‌کننده استفاده کنید. هر Variation با `ID:<variation_id>` خودش شناسایی و جفت می‌شود؛ نیازی به تغییر SKUهای مشترک نیست. ورود دستی SKU مشترک به‌دلیل مبهم‌بودن رد می‌شود.

= اگر محصول ArioCase فقط Product ID داشته باشد چه می‌شود؟ =
لینک محصول ساده در تبدیل‌کننده مرجع `ID:<product_id>` می‌سازد. برای Variation بدون SKU، مرجع `ID:<parent_id>/<variation_id>` ساخته می‌شود تا والد و تنوع هر دو مشخص باشند. این مراجع در Preview، اتصال و نگاشت داخلی حفظ می‌شوند و خواندن تازهٔ موجودی از Endpoint متناظر انجام می‌شود. SKU ساختگی ساخته نمی‌شود.

= اگر یکی از دو کد وجود نداشته باشد چه می‌شود؟ =
همان جفت با خطا رد می‌شود. هیچ محصول جدیدی ساخته نمی‌شود و هیچ نگاشتی ذخیره نمی‌شود.

= آیا موجودی بعد از فروش در ArioCase کم می‌شود؟ =
نه. این نسخه فقط خواندن ArioCase → TisaCase را انجام می‌دهد و کاهش/رزرو اتمیک در ArioCase ندارد؛ سینک دوطرفهٔ کامل ادعا نمی‌شود.

= آیا با سرویس واقعی تست شده است؟ =
قرارداد با Payloadهای WooCommerce آزمون شده، اما محیط ساخت اجازهٔ اتصال خروجی به ariocase.com نداشت. تست اتصال داخل سایت و Staging پیش از Production الزامی است.
