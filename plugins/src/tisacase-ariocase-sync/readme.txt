جفت‌کردن دو محصول موجود با SKU یا Product ID و تبدیل لینک محصول TisaCase یا ArioCase به شناسه؛ فقط و فقط برای سینک موجودی.

== Description ==

هر جفت یک کارت با دو فیلد مستقل شناسه دارد؛ یکی برای TisaCase و دیگری برای ArioCase. تطبیق هوشمند Variationها را در کارت‌های آکارئونی به تفکیک محصول گروه‌بندی می‌کند؛ با بازکردن هر محصول، جفت‌های پیشنهادی، مبهم و بدون جفت را همراه مرجع دقیق می‌بینید. نرمال‌سازی گسترده‌تر نام مدل، اعداد، رنگ، ظرفیت، واژه‌های تزئینی و صفر پیشرو کمک می‌کند شکل‌های متفاوت نوشتاری پیدا شوند، اما نسل 4G/5G و مدل‌های متفاوت همچنان جدا می‌مانند.

`AR120 - AR22`

اگر شناسهٔ یکی از دو فروشگاه را ندارید، لینک محصول را در «تبدیل لینک به شناسه» وارد کنید. فروشگاه از روی دامنه تشخیص داده می‌شود و SKU واقعی برای کپی نمایش داده می‌شود. اگر محصول ArioCase فقط Product ID داشته باشد، خروجی قابل‌کپی `ID:<product_id>` است. برای محصول متغیر، منوی «انتخاب Variation» باز می‌شود و شناسهٔ همان متغیر کپی می‌شود؛ شناسهٔ والد برای اتصال پیشنهاد نمی‌شود. برای Variation تیساکیس همواره `ID:<variation_id>` یکتا کپی می‌شود تا SKU مشترک بین والد و Variationها مانع اتصال نشود. کارت نتیجه در حالت اولیه مخفی است و بعد از تبدیل، مرتب و تمام‌عرض زیر فیلد لینک نمایش داده می‌شود. Selector فقط Variation واقعیِ دارای ID را نشان می‌دهد؛ دکمه یا گزینهٔ Attribute به‌تنهایی برای اتصال کافی نیست و Variation جدید ساخته نمی‌شود. تعداد Variationهای قابل‌اتصال در وضعیت نمایش داده می‌شود.

برای اتصال سریع همهٔ Variationهای دو محصول متغیر، لینک، SKU یا ID والد TisaCase و ArioCase را در کارت «تطبیق خودکار Variationها» وارد کنید و «یافتن جفت‌ها» را بزنید. موتور تطبیق، SKU و برچسب‌ها را از نظر حروف، فاصله، جداکننده، اعداد فارسی/عربی، برندهای معمول، معادل رنگ و واحد نرمال می‌کند؛ بنابراین `S25 Ultra` و `s25ultra` و همچنین `Samsung A56`، `SamsungA56` و `A56` معادل شناخته می‌شوند. برندهای `iPhone`، `Redmi`، `Poco` و `Mi` نیز بدون تغییر عدد یا پسوند مدل نرمال می‌شوند؛ اما مدل متفاوت مثل `S24` و `S25` یا `A55` و `A56` جفت نمی‌شود. SKU یا Label تکراری، رقابت چندتایی و مرجع خروجی تکراری رد می‌شود و هیچ مورد مبهمی به‌صورت خودکار انتخاب نمی‌شود. خروجی با ID دقیق Variation در کارت‌های جفت قرار می‌گیرد و همان Fresh Preview و تأیید اتصال قبلی لازم است. دسته‌ها حداکثر ۵۰ جفت دارند و «دسته بعد» باقی جفت‌ها را آماده می‌کند.

بلافاصله بعد از تطبیق، عنوان هر Variation زیر فیلد شناسهٔ همان فروشگاه نمایش داده می‌شود تا کاربر پیش از Preview صحت کد را ببیند. پس از Preview، این عنوان با نام واقعی Resolve‌شده به‌روز می‌شود؛ برای کدهای دستی هم همین نمایش انجام می‌شود. تغییر دستی کد، عنوان قبلی همان فیلد را پاک می‌کند تا نام و کد ناسازگار باقی نماند. این عنوان فقط نمایشی است و نام محصول تغییر نمی‌کند.

قالب خطی قبلی با دو SKU و قالب لینک‌دار نسخهٔ 1.3.0 برای سازگاری در لایهٔ پردازش حفظ شده است. لینک ArioCase با وب‌سرویس و لینک TisaCase از روی محصولات همان وردپرس Resolve می‌شود.

* کارت‌های جمع‌وجور با دو Input شناسه، پیش‌نمایش کارتی و دکمهٔ کپی شناسه.
* هر دو محصول باید از قبل وجود داشته باشند؛ هیچ محصولی ساخته نمی‌شود.
* فقط نگاشت داخلی و موجودی تغییر می‌کند.
* نام، قیمت، SKU، تصویر، توضیحات، ویژگی‌ها و وضعیت انتشار کپی یا سینک نمی‌شوند.
* هر SKU تیساکیس و هر کد ArioCase فقط در یک جفت فعال قرار می‌گیرد.
* پیش‌نمایش دو محصول قبل از اتصال و خواندن دوبارهٔ موجودی تازه هنگام اجرا.
* پشتیبانی از محصول ساده با ساده و Variation با Variation؛ والد متغیر مستقیماً سینک نمی‌شود.
* دریافت Variationهای محصول متغیر در تبدیل‌کننده؛ ID یکتا برای تیساکیس و SKU یا مرجع ID برای آریوکیس.
* تطبیق یک‌به‌یک و دسته‌ای Variationهای دو والد با کنارگذاشتن موارد مبهم و استفاده از مرجع دقیق ID.
* کنترل موجودی در افزودن به سبد، سبد و تسویه‌حساب با تجمیع تعداد هر قلم.
* عدم تبدیل Timeout، خطای HTTP یا JSON خراب به موجودی صفر.
* گزارش ۱۰۰ رویداد آخر بدون ذخیرهٔ Token و ثبت در TisaCase Hub.

== Installation ==

1. ووکامرس را فعال کنید و از سایت نسخهٔ پشتیبان بگیرید.
2. فایل `tisacase-ariocase-sync.zip` را از پیشخوان › افزونه‌ها › افزودن › بارگذاری نصب و فعال کنید.
3. به ووکامرس › جفت موجودی ArioCase › تنظیمات API بروید.
4. آدرس پیش‌فرض را حفظ کنید، روش Bearer را انتخاب و Token را در API Key وارد کنید.
5. با یک لینک، SKU یا مرجع `ID:<product_id>` واقعی «تست اتصال» را اجرا کنید.
6. برای دو محصول متغیر، مرجع دو والد را در «تطبیق خودکار Variationها» وارد کنید و جفت‌های یکتا را بسازید. برای اتصال تکی، از «تبدیل لینک به شناسه» و منوی Variation استفاده کنید.
7. کارت‌های ساخته‌شده را بررسی کنید؛ برای اتصال دستی هم شناسهٔ تیساکیس و آریوکیس را در فیلد همان فروشگاه قرار دهید.
8. پیش‌نمایش تازه را بررسی و فقط جفت‌های تأییدشده را متصل کنید؛ اگر بیش از ۵۰ جفت است، پس از اتصال «دسته بعد» را بزنید.

== ArioCase API contract ==

تنظیمات پیش‌فرض برای قرارداد اعلام‌شدهٔ ArioCase آماده است:

* Base URL: `https://ariocase.com/wp-json/wc/v3`
* Auth: `Authorization: Bearer YOUR_TOKEN`
* جست‌وجوی کد ArioCase: `products?status=publish&per_page=100&sku={code}`
* تشخیص لینک Pretty/Plain Permalink: `products?status=publish&per_page=100&slug={slug}`
* لینک کوتاه `?p={id}`، مرجع مستقیم `ID:<product_id>` و دریافت محصول شناسایی‌شده: `products/{id}`
* دریافت جزئیات تنوع‌ها هنگام نیاز: `products/{parent_id}/variations`
* خواندن موجودی تنوع شناسایی‌شده با مرجع `ID:<parent_id>/<variation_id>`: `products/{parent_id}/variations/{variation_id}`

پاسخ List با کد دقیق و حساس‌به‌حروف بررسی می‌شود. در مراجع `ID:<product_id>` و `ID:<parent_id>/<variation_id>`، IDهای پاسخ باید دقیقاً با مرجع درخواستی یکی باشند؛ ورودی عددی بدون پیشوند `ID:` همچنان SKU است. در حالت لینک، Host باید با دامنهٔ API تنظیم‌شده یکی باشد، خود صفحهٔ محصول Fetch نمی‌شود و Slug پاسخ باید دقیقاً با لینک یکی باشد. Product ID و Parent/Variation ID فقط برای یافتن همان محصول در درخواست‌های بعدی نگهداری می‌شوند.

== TisaCase link resolver ==

لینک TisaCase با Host سایت جاری تشخیص داده و بدون HTTP Request خارجی Resolve می‌شود. لینک کوتاه با Product ID و لینک `?product=slug` با محصول همان نامک خوانده می‌شود؛ Pretty Permalink ابتدا با Rewrite خود وردپرس به Product ID تبدیل می‌شود. اگر Rewrite نامک فارسی یا URL-encoded را نشناسد، نامک دقیق فقط در مسیر محصول و با `post_type=product` بررسی می‌شود؛ مسیر غیرمحصول پذیرفته نمی‌شود. برای محصول متغیر، Reader مستقیم و بدون `LIMIT` از جدول پست‌های همان وردپرس فقط `product_variation`های غیرحذف‌شده با `post_parent` دقیق همان والد را می‌خواند. نتیجهٔ خالی دیتابیس با Cache پر نمی‌شود؛ نوع و Parent ID هر Variation دوباره کنترل می‌شود و برچسب Taxonomy از Term واقعی خوانده می‌شود. هر Variation با مرجع `ID:<variation_id>` بازگردانده می‌شود و SKU در برچسب گزینه باقی می‌ماند؛ بنابراین SKU مشترک هم قابل‌استفاده است. SKU خالی در محصول ساده، لینک غیرمحصول و دامنهٔ ناشناس رد می‌شود.

== Security and stock behavior ==

* HTTPS الزامی است و Redirect دنبال نمی‌شود تا Token به مقصد دیگر منتقل نشود.
* Token نمایش داده نمی‌شود و از خطاها و گزارش‌ها حذف می‌شود.
* می‌توانید Token را با ثابت `TISACASE_ARIOCASE_API_KEY` در wp-config.php قرار دهید.
* خطای API به معنای موجودی صفر نیست و موجودی صفر را در دیتابیس بازنویسی نمی‌کند.
* با نگهبان خرید فعال، خرید قلم متصل هنگام نبود امکان بررسی موجودی متوقف می‌شود.
* حذف افزونه فقط نگاشت‌ها و تنظیمات خودش را پاک می‌کند؛ محصولات حذف نمی‌شوند.

== Stock request timing ==

* «تطبیق خودکار» فقط دو والد و Variationهای آن‌ها را می‌خواند و هیچ نگاشت یا موجودی ذخیره نمی‌کند.
* Preview برای هر جفت، موجودی فعلی ArioCase را می‌خواند. Connect پیش از ذخیرهٔ نگاشت، Preview و خواندن تازه را دوباره انجام می‌دهد؛ Snapshot کهنه استفاده نمی‌شود.
* پیش‌فرض امن `live_scope=purchase` است: Getterهای کاتالوگ و صفحهٔ محصول از آخرین Snapshot محلی استفاده می‌کنند و هر Snapshot قدیمی‌تر از ۵ دقیقه با WP-Cron در پس‌زمینه تازه می‌شود؛ درخواست عمومی PHP منتظر API آریوکیس نمی‌ماند.
* افزودن به سبد، بازبینی سبد و Checkout مستقل از کش، موجودی ArioCase را زنده کنترل می‌کنند؛ در خطای API خرید قلم متصل Fail-closed می‌شود.
* اگر WP-Cron روی هاست غیرفعال باشد، کاتالوگ آخرین Snapshot را نگه می‌دارد؛ کنترل زندهٔ خرید همچنان برقرار است.
* «همهٔ Getterها» گزینهٔ پیشرفتهٔ اختیاری است و هر محصول را هم‌زمان از API می‌خواند؛ برای کاتالوگ عمومی توصیه نمی‌شود. درخواست‌های AJAX هم در حالت پیشنهادی به API زنده وصل نیستند.
* دکمهٔ «سینک/به‌روزرسانی» Cache همان محصول را دور می‌زند و خواندن تازه انجام می‌دهد. زمان آخرین Snapshot پس از هر پاسخ موفق به‌روزرسانی می‌شود، حتی اگر مقدار موجودی تغییر نکرده باشد.
* ذخیرهٔ سه فیلد Stock محلی اختیاری است؛ افزونه فقط از ArioCase می‌خواند و موجودی آن فروشگاه را نمی‌نویسد.

== Frequently Asked Questions ==

= آیا نام یا قیمت هم بین دو فروشگاه سینک می‌شود؟ =
نه. هیچ فیلد محصول به‌جز `manage_stock`، `stock_quantity` و `stock_status` تغییر نمی‌کند. نگاشت و شناسه‌های API هم فقط Meta داخلی افزونه هستند.

= چه لینک‌هایی پشتیبانی می‌شوند؟ =
لینک محصول TisaCase یا ArioCase با Pretty Permalink مثل `/product/case-slug/`، نامک در Query مثل `?product=case-slug` و لینک کوتاه `?p=123`. دامنه باید با سایت جاری یا ArioCase تنظیم‌شده یکی باشد. لینک دسته‌بندی، برچسب یا دامنهٔ دیگر پذیرفته نمی‌شود. برای Variation، لینک والد را در تبدیل‌کننده وارد و متغیر را از منو انتخاب کنید؛ در تیساکیس ID یکتای Variation و در آریوکیس SKU یا مرجع ID همان Variation ساخته می‌شود.

= اگر SKU والد و Variationهای تیساکیس یکسان باشد چه می‌شود؟ =
از تبدیل‌کننده استفاده کنید. هر Variation با `ID:<variation_id>` خودش شناسایی و جفت می‌شود؛ نیازی به تغییر SKUهای مشترک نیست. ورود دستی SKU مشترک به‌دلیل مبهم‌بودن رد می‌شود.

= تطبیق خودکار چه مواردی را وصل نمی‌کند؟ =
SKU یا Label تکراری، چند کاندیدای هم‌امتیاز، استفادهٔ هم‌زمان یک Variation در چند جفت، مرجع خروجی تکراری و Variation بدون مرجع دقیق رد می‌شوند. تطبیق فقط کارت‌های جفت را آماده می‌کند؛ Preview تازه و تأیید کاربر همچنان اجباری است.

= اگر محصول ArioCase فقط Product ID داشته باشد چه می‌شود؟ =
لینک محصول ساده در تبدیل‌کننده مرجع `ID:<product_id>` می‌سازد. برای Variation بدون SKU، مرجع `ID:<parent_id>/<variation_id>` ساخته می‌شود تا والد و تنوع هر دو مشخص باشند. این مراجع در Preview، اتصال و نگاشت داخلی حفظ می‌شوند و خواندن تازهٔ موجودی از Endpoint متناظر انجام می‌شود. SKU ساختگی ساخته نمی‌شود.

= اگر یکی از دو کد وجود نداشته باشد چه می‌شود؟ =
همان جفت با خطا رد می‌شود. هیچ محصول جدیدی ساخته نمی‌شود و هیچ نگاشتی ذخیره نمی‌شود.

= آیا موجودی بعد از فروش در ArioCase کم می‌شود؟ =
نه. این نسخه فقط خواندن ArioCase → TisaCase را انجام می‌دهد و کاهش/رزرو اتمیک در ArioCase ندارد؛ سینک دوطرفهٔ کامل ادعا نمی‌شود.

= آیا با سرویس واقعی تست شده است؟ =
قرارداد با Payloadهای WooCommerce آزمون شده، اما محیط ساخت اجازهٔ اتصال خروجی به ariocase.com نداشت. تست اتصال داخل سایت و Staging پیش از Production الزامی است.

* کنترل مجدد نوع و Parent ID، حذف ID تکراری، خواندن برچسب Term برای Taxonomy و ممنوعیت جایگزینی نتیجهٔ صفر دیتابیس با Cached Children.
* رگرسیون SQL مستقیم، ۷۵ Variation، والد/نوع نامعتبر، Taxonomy و Fallback فقط هنگام نبود لایهٔ دیتابیس؛ حفظ Smart Match و قرارداد Stock-only.

= 1.8.4 =
* خواندن همهٔ Variationهای TisaCase مستقیم از دیتابیس وردپرس با `post_parent` والد، `post_type=product_variation` و `post_status=any`.
* حذف وابستگی مسیر اصلی Load به Transient فهرست فرزندها و فیلترهای `woocommerce_variable_children_args`/`woocommerce_get_children`؛ بدون سقف تعداد و بدون فیلتر Visibility یا Stock.
* رگرسیون با Cache ناقص و ۷۵ Variation واقعی؛ حفظ ID دقیق، SKU مشترک، Smart Match و عدم ساخت Variation از Attribute option.

= 1.8.3 =
* اصلاح Resolve لینک Pretty Permalink فارسی و URL-encoded تیساکیس وقتی `url_to_postid()` محصول را برنمی‌گرداند.
* Fallback دقیق نامک محصول در هر دو شکل ذخیرهٔ Encoded و Decode‌شده، محدود به مسیر محصول و بدون پذیرش لینک دسته‌بندی یا ساخت مرجع جعلی.
* رگرسیون با لینک «قاب براش لیلیوم» و حفظ Load واقعی Variationها، Smart Match و رفتار Stock-only.

= 1.8.2 =
* اصلاح Smart Match برای عبور پاسخ خام ArioCase از همان Resolver تبدیل‌کننده؛ ساخت `reference`، `label` و ID تنوع پیش از Matcher.
* پشتیبانی یکسان از لینک، SKU و ID والد ArioCase در مسیر تطبیق و حفظ مرجع دقیق `ID:<parent_id>/<variation_id>` در خروجی.
* رگرسیون یکپارچه با ۱۷ و ۳۳ Variation: هشت جفت یکتا، ۳۴ مورد کنارگذاشته و عدم جفت `A56` وقتی فقط Attribute option والد است.
* حفظ تطبیق یک‌به‌یک، Fresh Preview و رفتار Stock-only بدون تغییر.

= 1.8.1 =
* Load صریح همهٔ Variationهای واقعی والد و نمایش تعداد موارد قابل‌اتصال در Selector و Smart Match.
* شفاف‌سازی تفاوت Attribute option با Variation دارای ID؛ هیچ Variation یا مرجع جعلی ساخته نمی‌شود.
* تطبیق `Samsung A56 = A56` و حالت چسبیدهٔ `SamsungA56`؛ افزودن برندهای `Poco` و `Mi` و پوشش برند چسبیدهٔ iPhone/Redmi.
* تست جدایی مدل‌های `A55` و `A56` و حفظ محافظت یک‌به‌یک و Fresh Preview.

= 1.8.0 =
* افزودن تطبیق خودکار Variationهای دو محصول متغیر و ساخت دسته‌ای کارت‌های جفت.
* نرمال‌سازی SKU/Label، فاصله و جداکننده، اعداد فارسی/عربی، معادل مدل/رنگ و ترتیب Tokenها؛ مثل `S25 Ultra` با `s25ultra`.
* تطبیق فقط یک‌به‌یک با اولویت SKU یکتا، رد موارد مبهم/تکراری و استفاده از `ID:<parent_id>/<variation_id>` دقیق برای ArioCase در خروجی هوشمند.
* اتصال دسته‌های حداکثر ۵۰جفتی با «دسته بعد» و حفظ اجباری Fresh Preview و Fresh Read پیش از Connect.
* نمایش عنوان Variation زیر فیلد هر فروشگاه بعد از تطبیق و Preview، با پاک‌شدن عنوان کهنه هنگام ویرایش کد.
* مستندسازی زمان دقیق درخواست‌های Stock و حفظ کامل رفتار Pair-only نسخهٔ قبل.
